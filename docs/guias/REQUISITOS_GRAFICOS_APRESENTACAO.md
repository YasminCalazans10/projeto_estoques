# Requisitos para Construcao dos Graficos e Apresentacao

Este guia deve ser enviado aos alunos como referencia para a entrega dos graficos e para a apresentacao em sala.

## 1. Prazo e expectativa de entrega

- O arquivo do grupo deve ser atualizado ao longo do desenvolvimento.
- A versao final deve estar concluida ate `28/04`.
- Ate `28/04`, o grupo deve estar com o Git do projeto atualizado antes da apresentacao.
- No dia `28/04`, cada grupo fara a apresentacao na turma.
- Durante a apresentacao, o grupo deve explicar como organizou o trabalho, quais decisoes tomou e como construiu os graficos.

## 2. Requisitos gerais para todos os grupos

- O dashboard deve usar dados reais do projeto, sem graficos preenchidos manualmente no frontend.
- Os graficos precisam estar ligados aos filtros da pagina correspondente.
- Cada grafico deve ter titulo claro, legenda quando necessario e eixos identificados.
- Os valores exibidos devem estar coerentes com os KPIs e com as views materializadas do projeto.
- O grupo deve justificar a escolha de cada grafico, explicando o que ele mostra e por que ele ajuda na analise.
- A pagina precisa funcionar sem erro durante a demonstracao.
- O grupo deve apresentar evidencias de divisao de trabalho, mostrando como os integrantes contribuiram para a entrega.

## 3. Estrutura esperada da explicacao em sala

- Apresentar rapidamente o objetivo do bloco analisado.
- Mostrar os filtros utilizados e como eles alteram a leitura dos dados.
- Explicar cada grafico criado, destacando a interpretacao principal.
- Relacionar os graficos aos KPIs do bloco.
- Informar como o grupo implementou a solucao no projeto.

## 4. Requisitos por bloco de analise

## 4.1 Bloco 1 - Vendas

- Construir graficos que permitam analisar faturamento, margem, volume e evolucao no tempo.
- Representar pelo menos uma comparacao entre filiais, cidades, regioes ou segmentos.
- Incluir pelo menos um grafico temporal para mostrar variacao mensal.
- Relacionar os graficos com KPIs como `receita_liquida`, `margem_bruta_pct`, `ticket_medio`, `itens_por_pedido` ou `crescimento_receita_pct`.
- Explicar quais conclusoes de negocio podem ser tiradas a partir dos resultados.

## 4.2 Bloco 2 - Produtos

- Construir graficos que permitam analisar portfolio, demanda, precificacao e renovacao de produtos.
- Representar pelo menos uma comparacao por categoria, fornecedor ou regiao.
- Incluir pelo menos um grafico temporal para mostrar crescimento ou queda em unidades e comportamento do portfolio.
- Relacionar os graficos com KPIs como `taxa_lancamento_pct`, `taxa_descontinuacao_pct`, `markup_medio_pct`, `demanda_media_por_produto` ou `crescimento_unidades_pct`.
- Explicar como os graficos apoiam decisoes sobre mix de produtos e desempenho comercial.

## 4.3 Bloco 3 - Estoques

- Construir graficos que permitam analisar disponibilidade, ruptura, cobertura e capital em estoque.
- Representar pelo menos uma comparacao por centro de distribuicao, familia, filial ou regiao.
- Incluir pelo menos um grafico temporal para mostrar oscilacoes de estoque ao longo dos meses.
- Relacionar os graficos com KPIs como `taxa_ruptura_pct`, `giro_estoque`, `dias_cobertura_medio`, `valor_estoque_total` ou `variacao_valor_estoque_pct`.
- Explicar como os resultados indicam risco de falta, excesso de estoque ou necessidade de ajuste operacional.

## 5. Fechamento obrigatorio do grupo

- O material deve estar revisado e finalizado ate `28/04`.
- O repositorio Git do projeto deve estar atualizado antes da apresentacao.
- O grupo deve levar a versao pronta para apresentar na turma.
- Todos devem estar preparados para explicar a participacao do grupo na construcao da entrega.
